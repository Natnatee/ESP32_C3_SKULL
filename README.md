# ESP32_C3_SKULL

หัวกะโหลก Halloween: AM312 ตรวจคนแล้วเล่นเสียงสุ่ม พร้อมขยับกราม MG995 และไฟตาแดง เอกสารนี้เป็นสเปกระบบรวม ไม่ใช่ผลยืนยันการทดสอบฮาร์ดแวร์

## Boot self-test: 10 วินาทีแรก
- กรามเริ่ม 5 รอบทันที: เปิด 1200 / ปิด 1600 µs ขาละ 1 วินาที เริ่มส่ง PWM ที่ 1500 µs แล้วติดตามคลื่นสามเหลี่ยม 1200–1600 µs การเคลื่อนที่จริงครั้งแรกอาจเร็ว
- ตาทั้งคู่กระพริบสลับติด/ดับทุก 150 ms เฉพาะขณะ PIR GPIO10 HIGH ไม่ใช่หลักฐานว่า PIR ปกติ เพราะเซ็นเซอร์อาจอยู่ช่วงตั้งตัว **นี่ไม่ใช่ PIR warmup**
- DFPlayer initialize ประมาณ 4 วินาที เมื่ออ่านจำนวนไฟล์ SD ได้และ player ว่าง เล่น global track สุ่มหนึ่งเพลงทันที เสียงเริ่มที่วินาที 0 ไม่ได้ ต้องรอ SD พร้อม จึงเล่นได้เฉพาะเวลาที่เหลือของหน้าต่าง self-test ไม่ใช่เต็ม 10 วินาที
- ครบ 10 วินาทีสั่ง STOP แม้เสียงยังไม่จบ ดับตาและปิดกราม รออย่างน้อย 300 ms หลัง STOP พร้อม BUSY idle แล้วเข้าโหมดปกติ ต้องพบ PIR LOW ก่อน HIGH ใหม่ **ไม่มี cooldown หลัง boot**
- หากอ่านจำนวนไฟล์ไม่สำเร็จ เข้า FAULT หยุดเอฟเฟกต์ก่อนกำหนด หยุดเสียง ดับตาและสั่งปิดกราม

## การทำงานปกติ
- ทุก trigger เริ่มกรามและตาทันที ไม่รอเสียงเริ่ม ใช้ DFPlayer BUSY (LOW = กำลังเล่น) ติดตามเสียง **ต้องต่อสาย BUSY** ไม่รับ trigger ใหม่ระหว่างเสียง/เอฟเฟกต์และ cooldown
- สุ่มเสียงแบบ shuffle bag: สับ global index 1 ถึงจำนวนไฟล์ SD ที่อ่านด้วย `0x48` เล่นครบทุกไฟล์โดยไม่ซ้ำในชุด แล้วสับชุดใหม่ หลีกเลี่ยงซ้ำติดกันข้ามชุดเมื่อมีมากกว่า 1 ไฟล์ เสียง self-test นับเป็นหนึ่งไฟล์ที่เลือกในชุดด้วย รีสตาร์ตเริ่มชุดใหม่ เล่นด้วย `0x03` ไม่แมปชื่อไฟล์ ไม่สุ่มหมวดหมู่ นับเมื่อสั่งเล่น ไม่ใช่เมื่อเล่นจบ
- สุ่มรูปแบบตาแยกจากเสียงอย่างสม่ำเสมอ: ติดค้าง / สลับข้าง / กระพริบพร้อมกันช้า / กระพริบพร้อมกันเร็ว
- กรามเริ่มปิด 1600 → เปิด 1200 µs ใน 1 วินาที → ปิด 1600 µs ใน 1 วินาที ทำซ้ำ 5 รอบ รวม 10 วินาที ไม่มีสุ่มเป้าหมายกราม ตารูปแบบที่สุ่มทำงานตลอด 10 วินาทีเดียวกัน
- เสียงสั้น: เอฟเฟกต์ยังทำงานจนครบ 10 วินาที; เสียงยาว: หลัง 10 วินาทีกรามปิดและตาดับ แต่เสียงเล่นจนจบตามธรรมชาติ ไม่ตัดที่ 10 วินาที (ยังมี safety 60 วินาที)
- เริ่ม cooldown 10 วินาทีหลัง **ทั้งเสียงและเอฟเฟกต์จบแล้ว** จากนั้นต้องพบ PIR LOW อีกครั้งก่อนรับขอบขาขึ้นรอบใหม่
- รอเสียงเริ่มได้ไม่เกิน 5 วินาที; safety จำกัดเล่น 60 วินาที เมื่อ start timeout/player error ยกเลิกเอฟเฟกต์ สั่งหยุดเสียง ปิดกรามอย่างปลอดภัย ดับตา และเข้า cooldown
- เสียงเริ่มต้น **30/30 (สูงสุด)** ปรับได้ในเฟิร์มแวร์ ระวังเสียงแตก ความร้อน และไฟเลี้ยงตก โดยเฉพาะเมื่อ servo ทำงานพร้อมกัน ไม่มี Wi-Fi

## ต่อสาย
| อุปกรณ์ | การต่อ |
|---|---|
| MG995 signal | GPIO4, PWM 50 Hz |
| ตาแดงซ้าย / ขวา | GPIO0 / GPIO1 → R แยกแต่ละดวง → anode LED; cathode → GND (active HIGH) |
| AM312 | OUT → GPIO10, VCC → 3.3V, GND ร่วม |
| DFPlayer RX | GPIO21 (ESP TX) ผ่าน R 1 kΩ |
| DFPlayer TX | GPIO20 (ESP RX) |
| DFPlayer BUSY | GPIO7; LOW ขณะเล่น |
| ลำโพง | SPK1–SPK2 ห้ามต่อขั้วใดลง GND |

ตรวจระดับ DFPlayer TX/BUSY ของโมดูลจริงตาม datasheet และวัดจริง หากสูงกว่า 3.3V ต้องลดระดับ เช่น voltage divider ก่อนเข้า ESP32; R 1 kΩ ที่สาย ESP TX ไม่ได้ป้องกันขารับสองเส้นนี้

## กรามและความปลอดภัย
- ช่วงคาลิเบรต: เปิด 1200 µs / ปิด 1600 µs; เริ่มต้นส่ง 1500 µs แล้วเข้า triangle self-test 1200–1600 µs ทันที; เมื่อจบปิดที่ 1600 µs และเมื่อ trigger ปกติใช้รอบเปิด–ปิดตามข้างต้น
- การเคลื่อนที่จริงครั้งแรกอาจเร็ว เพราะไม่ทราบตำแหน่งเดิมของเซอร์โว; ramp ไม่รับประกันความนุ่มนวลตอนเริ่มจ่ายไฟ และค่าพัลส์ไม่ใช่มุม feedback
- เตรียมสวิตช์ตัดไฟ ห้ามเอานิ้วเข้ากลไก หากชน ฝืน คราง หรือร้อน ให้ตัดไฟทันที การสั่งปิดกรามไม่ใช่ emergency stop

## ไฟเลี้ยง
ใช้ 18650 สองก้อนแบบ **2S** → BMS 2S → LM2596 ปรับเอาต์พุตเป็น **5V ก่อนต่อโหลด** แยกแขนงไป ESP32 ขา **5V ไม่ใช่ 3V3**, MG995 และ DFPlayer โดยใช้ GND ร่วม ห้ามป้อนแรงดันแบตเตอรี่ตรงเข้าอุปกรณ์

- ใช้เครื่องชาร์จ Li-ion 2S 8.4V ที่เหมาะสม; BMS ไม่ใช่เครื่องชาร์จ ตรวจพิกัดเซลล์ BMS สาย สวิตช์ และการป้องกันลัดวงจร
- MG995 มีกระแสกระชาก/ติดขัดสูง อย่าอาศัยตัวเลขกระแสโฆษณา LM2596 ต้องตรวจแรงดันตก กระแสและความร้อนจริง; แยกทางกระแสมอเตอร์จากสายเล็กของบอร์ด
- ใกล้ servo ใส่ C 1000 µF; ใกล้ DFPlayer ใส่ 470–1000 µF ร่วมกับ 0.1 µF ตรวจขั้ว/พิกัดแรงดัน C ไม่ทดแทนแหล่งจ่ายที่กระแสไม่พอ
- ห้ามเสียบ USB พร้อมไฟภายนอก เว้นแต่มีวงจรป้องกัน backfeed/แยกแหล่งจ่ายที่ตรวจสอบแล้ว ถอดไฟภายนอกก่อนอัปโหลดผ่าน USB

## microSD / เสียง
ฟอร์แมต FAT32 หลังสำรองข้อมูล คัดลอก **เนื้อหาทั้งหมดของ `public/sound/` (WAV 14 ไฟล์)** ลง root ของ SD คงชื่อและต้นฉบับไว้ ไม่คัดลอกเป็นโฟลเดอร์ `sound` และไม่ใส่เสียงอื่นปะปน

ไฟล์จริงเป็น WAV PCM 16-bit mono 24 kHz ต้องทดสอบความเข้ากันได้กับ DFPlayer จริง ลำดับ global index ขึ้นกับการจัดเก็บในการ์ด ไม่ใช่เลขหรือชื่อไฟล์

## ทดสอบเฉพาะ PIR + LED ผ่าน USB
ระบบเต็มต้องรอ DFPlayer พร้อม แต่เมื่อรับ trigger จะเริ่มตา/กรามทันทีโดยไม่รอ BUSY หากต่อแค่ PIR/LED ใช้โหมดแยก `pir_led_test` (`pir_led_test.cpp`, PIR GPIO10) แทน ไม่มี UART DFPlayer และไม่มี servo PWM ให้ถอดไฟ servo โหมด diagnostic นี้ยังคง warmup 30 วินาที ต่างจากระบบเต็ม

```sh
pio run -e pir_led_test -t upload
pio device monitor -b 115200
```

รัน upload เพียงครั้งเดียวและเปิด monitor แยกคำสั่ง ปิด monitor เดิมก่อน upload ไม่ต้องอัปโหลดซ้ำเพื่อเปิด monitor ถ้ามีหลายพอร์ตระบุ `--port` ของ monitor ตามบอร์ดจริง

เปิดเครื่องไฟซ้าย 1 วินาที ขวา 1 วินาที ทั้งคู่ 1 วินาที แล้วดับ รอ PIR warmup รวม 30 วินาที ให้ PIR LOW ก่อนเดินผ่าน จะแสดงไฟ 4 แบบรวม 8 วินาที จากนั้นพัก 10 วินาที Serial แสดงค่า GPIO10 ทุก 2 วินาทีและเมื่อเปลี่ยนสถานะ ทดสอบ LED0/1 ผ่าน R ลง GND, AM312 VCC3.3V OUT10 GNDร่วม

กลับระบบเต็มด้วย `pio run -e esp32c3 -t upload` environment default ยังเป็น `esp32c3`

ข้อผิดพลาด `upload -> upload` ยังไม่ทราบต้นเหตุจาก log เพียงอย่างเดียว ตรวจแล้ว project config/list targets ปกติ ต้องดูคำสั่งหรือ task ที่เรียกจริง ไม่ได้อ้างว่าแก้ dependency cycle แล้ว

## พัฒนา / ตรวจสอบ
PlatformIO + Arduino บน ESP32-C3 คง board ID `lolin_c3_mini` ใช้ LEDC ของ ESP-IDF และ `HardwareSerial` ที่มากับ framework ไม่เพิ่ม dependency โค้ดทดสอบกรามเก่าอยู่ `include/jaw_test.cpp.txt`

```sh
pio run
pio run -t upload
pio device monitor
```

Full build (`esp32c3`) ผ่านแล้วตามผลที่แจ้งสำหรับ revision ก่อนการแก้ล่าสุด และกำลังรัน final build ซ้ำ ยังไม่ได้อัปโหลดหรือทดสอบฮาร์ดแวร์ ต้องตรวจไฟเลี้ยง, BUSY, เสียงครบ 14 ไฟล์, PIR/cooldown, ตา และกรามจริงก่อนใช้งาน ดูรายละเอียดใน `project.md` และ `hardware_lib.md`
